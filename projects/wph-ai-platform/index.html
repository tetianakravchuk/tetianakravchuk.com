The problem

Publishing intelligence is fragmented

Information about publishers, books, languages, translations, release timing, and rights signals is distributed across many sources. The product goal is to organize this information without presenting unsupported conclusions as fact.

My role

Founder and applied AI engineer

I designed the product architecture, data workflows, AI-assisted research patterns, evaluation rules, observability, analytics, and quality strategy. This is an independent portfolio product, not employer work.

Architecture

How the system works

1. Research and ingestion

Research agents and ingestion workflows collect structured publishing information, preserve source context, normalize records, and stage candidates for review.

2. Evaluation and guardrails

Deterministic checks evaluate source grounding, factual consistency, duplicate risk, unsupported claims, and trust-and-safety language before content is promoted.

3. Analytics and observability

PostgreSQL-backed metrics track source health, ingestion quality, latency, failures, token usage, model cost, prompts, agents, and workspace budgets.

What I built

  • Autonomous research-agent workflows with structured tool use.
  • Source-backed retrieval and multilingual metadata enrichment.
  • LLM evaluation fixtures for safe and unsafe output patterns.
  • Request tracing, model usage, latency, cost, and failure telemetry.
  • Prompt registry workflows with evaluation-gated promotion and rollback.
  • PostgreSQL analytics for publisher coverage, release trends, and source health.
  • REST APIs, admin dashboards, regression tests, and technical documentation.

Quality principles

  • Separate retrieved evidence from generated interpretation.
  • Never infer rights availability from missing information.
  • Preserve provenance and verification status.
  • Make partial coverage visible to users.
  • Measure AI behavior using repeatable evaluation fixtures.
  • Track operational cost and failures, not only output quality.
