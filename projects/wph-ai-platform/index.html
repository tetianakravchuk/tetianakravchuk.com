Evidence before confident answers

Problem

International publishing data is scattered across catalogs, publisher sites, and rights records. An LLM can summarize it fluently and still invent a translator or imply rights that do not exist.

What I built

World Publishing Houses is a live full-stack product built with Next.js, FastAPI, and PostgreSQL. Records carry source evidence and review state; unverified evidence remains visibly pending.

My role

Sole founder-engineer: product architecture, data pipelines, agent workflows, evaluation, testing, and release.

Proof

  • Recovered Sweden discovery: five consecutive production runs reached human review with matching counts—22 verified and 3 pending.
  • Built a 100-case golden set across five risk categories, with a hard rights-safety gate.
  • 774 backend and 420 frontend tests passed at the last stabilization milestone.
Evaluation & quality engineering

Failures I found and fixed

These are concrete defects in evidence handling and recovery—and the checks that keep them from returning.

Evidence integrity

A changed claim kept the same receipt

Symptom: Changing a claim’s expected value changed its verdict, but not its evidence-receipt hash.

Fix: Bind the expected value into the receipt.

Proof: A regression test failed before the fix and passed after; the focused suite grew from 9 to 10 tests.

Evaluation integrity

Aliases looked like independent sources

Symptom: Duplicate source aliases could count as two independent confirmations.

Fix: Resolve source identities before counting corroboration.

Proof: Adversarial cases verify aliases cannot inflate independent support.

Unicode integrity

Look-alike characters could distort a name

Symptom: Cyrillic Ё and Latin Ë could split the same name—or make distinct names look alike.

Fix: Normalize comparison forms while preserving the original string for inspection.

Proof: Acceptance cases cover mixed-script names and preserve the source text.

Pipeline reliability

Remote connection drops stopped discovery

Symptom: Sweden discovery runs died when remote connections closed.

Fix: Handle targeted network errors; leave timed-out sources verification_pending instead of guessing.

Proof: Five consecutive production runs reached review with matching counts and individual trace IDs.

System architecture

Data first, AI second

WPH keeps source records and verification state in the system of record. Research and evaluation workflows sit around that evidence; they cannot silently promote an unsupported claim.

Evaluation system

Quality is a release property

The golden set makes risk coverage explicit. Safety-critical failures block promotion even when other scores are strong.

Deterministic checks cover schema, citations, duplicates, provenance, safety, cost, latency, and safe abstention.

Hard safety gate

Missing evidence is not evidence of rights

Safe: “No English edition was found in the reviewed sources.”

Unsafe inference: “English rights are available.”

Rights safety cannot be averaged away by strong scores elsewhere. Human review remains part of promotion.

Ownership & next steps

Tradeoffs and what’s next

Tradeoff

PostgreSQL first

I kept one primary system of record rather than adding specialized databases before the product required them.

Tradeoff

Deterministic safety

Safety rules stay outside model judgment so an evaluator cannot vote away a prohibited rights claim.

Tradeoff

Evidence-first retrieval

Build immutable source snapshots, provenance, canonical URLs, and trust tiers before adding vector retrieval.

What’s next

Phase 2 acceptance

Complete isolated acceptance checks for recovery, staging data, and the production release path.

Evidence Verification Agent

Extend human review with a bounded assistant that checks claims against source evidence and preserves reviewer control.

Nordic bibliographic API

Model a cross-market discovery API on Denmark’s DBC FBI API, with country-specific evidence and shared cross-language search.

Scope & transparency

What’s live vs. what’s a demo

PartWhat it does today

Research workflowsSource discovery and validation are implemented as bounded, tool-driven workflows. The public code reviewed for this case study does not show a configured production LLM provider or an end-to-end model-generated answer path.
